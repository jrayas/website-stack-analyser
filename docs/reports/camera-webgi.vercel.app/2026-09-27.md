## Evidence and Uncertainties

- **Strongest evidence:** The page's own meta description names its exact technology ("Threejs demo landing page... using WEBGi — by Neotix"), removing any doubt about the core 3D stack. The `parcelRequire` string is Parcel's own runtime function name and cannot reasonably come from another bundler. GSAP and ScrollTrigger are named directly as bare strings matching their public npm package/plugin names.
- **Direct observations vs deductions:** Direct: WEBGi/Neotix self-description, `THREE.*` classes, `DRACOLoader`, `gsap`/`ScrollTrigger` strings, `parcelRequire`, Google Fonts link, Vercel headers. Deduction: absence of a JS framework (React/Vue/etc.) is inferred from the absence of typical framework fingerprints and the presence of plain hand-authored HTML structure — this is evidence of absence, not proof, since a framework could theoretically leave no detectable string trace after aggressive minification.
- **Unresolved questions:**
  - Exact versions of Three.js, WebGi, GSAP, and Parcel — none stated directly; would require an exposed manifest or source map.
  - Whether WebGi is used via its public npm package (`webgi`) or a custom/licensed build — Neotix is a named agency/studio (`author: www.neotix.com.br`), and WebGi is itself a commercial product by another company (Pixotronics), so licensing terms for direct reuse are unclear from public evidence alone.
  - Exact 3D model format and source (likely a Draco-compressed glTF/GLB given `DRACOLoader`) — not directly located in this pass.

## Recreation Guidance

- **Recommended minimal dependency set (recommendation, not a confirmed fact about the original site's exact package list):** Three.js for the underlying 3D engine, WebGi (a commercial/licensed product — check its own licensing before reuse) or a custom Three.js scene setup as a substitute, GSAP with the ScrollTrigger plugin for scroll-driven animation, Parcel (or any modern bundler such as Vite) for the build, and Google Fonts (DM Sans) for typography.
- **Version constraints:** None verified from public evidence; use current stable releases.
- **Unknowns to investigate before implementation:** Confirm WebGi's licensing model before depending on it directly (it's a commercial rendering toolkit); if avoiding it, a custom Three.js + DRACOLoader setup can achieve similar Draco-compressed model loading without the dependency.
